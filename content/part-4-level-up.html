If 50 tests all repeat the same base URL, header and login, one change means 50 edits. A specification (spec) holds the shared part once.

  • RequestSpecification: shared settings for the request (base URI, headers, auth, logging).
  • ResponseSpecification: shared checks (status 200, JSON type, response time).
Good to know
  • You can add more to a spec per test: given().spec(reqSpec).queryParam("page", 2).
  • Put your specs in one class (for example Specs.java) so the whole team shares them.
  • In parallel tests, avoid changing the global settings (they are shared). Pass a spec instead.
Interview question

"How do you avoid duplicate code in your API tests?" Answer: request and response specs, a base test class, POJOs for bodies, and small helper or service classes.

A POJO ("plain old Java object") is a simple class with fields, getters and setters. It mirrors a JSON shape. REST Assured turns it into JSON and back for you.

  • Serialization: Java object → JSON (when you send).
  • Deserialization: JSON → Java object (when you read).

You need Jackson (or Gson) in your pom for this. Without it you get an error.

When to use which
  • String / text block: quick demo or odd JSON.
  • Map: small bodies, quick tests.
  • POJO: real projects. Safer, reusable, and the compiler catches typos.

Many teams also use Lombok (@Data, @Builder) to skip writing getters and setters.

A JSON schema is a file that describes the shape of a response: which fields must exist and what type each one is. One line in your test checks all of it.

Schema vs value checks

Schema checks shape and types ("price is a number"). It does not check values ("price is 45"). Use both: schema for structure, body() for important values.

Try a validator

Change the response and press Validate. Try removing title, or changing price to a string.

Tip

No need to write a schema by hand. Paste a sample response into an online "JSON to schema" tool, then tighten it. Add "additionalProperties": false if extra fields should fail the test.

Note

XML numbers come back as text. Compare with "2", or convert first. REST Assured can send SOAP messages as XML, but a SOAP-focused tool is usually a better fit.

When a test fails, the first question is "what did we send and what came back?" Logging answers it.

Call Prints
log().all() everything
log().body() only the body
log().headers() only headers
log().ifError() only if the status is 4xx or 5xx
log().ifValidationFails() only if a check fails

Filters

A filter sits between your test and the server and can look at or change every call. Teams use filters for logging, reports and adding headers.
