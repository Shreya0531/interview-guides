Why the two "import static" lines?

Without them, you must write RestAssured.given() and Matchers.equalTo(1) every time. A static import lets you write given() and equalTo(1) alone. Everyone uses them, so you will see them in every interview example.

Setup errors you will meet
  • given() is red → you forgot import static io.restassured.RestAssured.*;
  • equalTo() is red → you forgot import static org.hamcrest.Matchers.*;
  • matchesJsonSchemaInClasspath not found → add the json-schema-validator dependency.
  • Odd errors after adding JUnit → put rest-assured above junit in the pom (a known library order problem).

Every REST Assured test tells a small story in three parts. It comes from a way of writing tests called BDD (behaviour-driven development).

given()

Set the scene. Everything about the request: base URL, headers, parameters, body, login.

when()

Do the action. Choose the method and path: get("/books"), post(...).

then()

Check the result. Status code, headers, body values, response time.

Other ways to write the same test

The style is only a habit. These all work.

Tiny details
  • and() and with() do nothing. They only make the line read better: .given().header(...).and().body(...).
  • You can write many checks after then(). REST Assured tests all of them and reports every failure together.
  • The semicolon goes only at the very end.
Interview favourite

"What is given-when-then?" Answer: "It is the BDD style. given prepares the request, when sends it, then validates the response. It makes tests easy to read, even for people who do not code."
