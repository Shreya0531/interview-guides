An API is a way for one program to talk to another program. Think of a restaurant. You (the client) tell the waiter (the API) what you want. The waiter goes to the kitchen (the server) and brings your food (the response) back.

Request and response

Every API call is a pair: you send a request, the server sends back a response. In API testing, your test code plays the client and checks the response.

→
Requestmethod + URL + headers + body
→
Serverthe API
→
Responsestatus code + headers + body

A request has

  • Method: what to do (GET, POST…)
  • URL: where to do it
  • Headers: extra info (like login token)
  • Body: data you send (optional)

A response has

  • Status code: did it work? (200, 404…)
  • Headers: info about the answer
  • Body: the data you get back
  • Time: how long it took

Read a URL

A URL is an address. REST Assured has a separate place for each part of it, so you must know the parts.

HTTP methods

The method tells the server what you want to do. Two words you must know for interviews:

  • Safe: does not change any data on the server.
  • Idempotent (say: eye-dem-POH-tent): calling it many times leaves the server in the same state as calling it once.
Method Use it to Safe? Idempotent? Usual success code
GET Read data Yes Yes 200
POST Create something new No No 201
PUT Replace the whole thing No Yes 200 or 204
PATCH Change only some fields No Not always 200
DELETE Remove something No Yes 200 or 204
HEAD Like GET, but headers only Yes Yes 200
OPTIONS Ask what is allowed Yes Yes 200
Easy example

Delete book 7 three times. After the first call the book is gone. The next calls change nothing more. That is idempotent. Create a book three times with POST and you get three books. That is not idempotent.

Interview favourite: PUT vs PATCH

PUT sends the full object and replaces the old one. PATCH sends only the fields that change. If you PUT without the "year" field, the year may be erased. With PATCH it stays.

Status codes

The first digit tells you the story: 2 = good, 3 = go somewhere else, 4 = you made a mistake, 5 = the server has a problem.

401 vs 403

401 = "I do not know who you are" (not logged in, or bad token). 403 = "I know who you are, but you may not do this" (no permission).

What does "REST" mean?

REST is a set of simple rules for building APIs. You do not need the textbook. Remember these:

  • Resources have URLs. A book is /books/7, not /getBook?id=7. Use nouns in the URL.
  • Methods are the verbs. GET reads, POST creates, and so on.
  • Stateless. The server does not remember you between calls. Each request carries what it needs, like a token.
  • Client and server are separate. They only talk through requests and responses.
  • Usually JSON. Data travels as text, most often JSON.
REST SOAP
A style, uses normal URLs and methods A strict protocol with its own rules
JSON (or XML) XML only
Light and fast Heavier, more built-in security rules
REST Assured is made for this Needs other tools (like SoapUI)

JSON is plain text that holds data in a neat shape. Almost every REST API sends and receives JSON.

The five building blocks

Piece Looks like In the example
Object { "key": value } the whole thing, and author
Array (list) [ a, b, c ] tags
String "text" in double quotes "Clean Code"
Number 7 or 32.5 id, price
Boolean / null true false null inStock, discount
Common JSON mistakes
  • Keys and strings need double quotes. Single quotes are not valid.
  • No comma after the last item.
  • No comments are allowed inside JSON.

To check a value in a test, you must say where it is. Use a dot to go inside an object and [0] to pick an item from a list (counting starts at 0). Click any value below to see its path.

The server also says which one it sends in a header: Content-Type: application/json. REST Assured reads this header to decide how to read the body.

REST Assured is a free Java library for testing REST APIs. You write a few lines of Java that send a request and check the response. The code reads almost like English.

HTTPthe network call
→
Your APIthe thing under test

Why teams choose it

  • Short code. A full test can be 6 lines.
  • Easy to read. The given / when / then style tells a story.
  • It is just Java. Use loops, classes, files and your own helpers.
  • Fits CI/CD. Runs with Maven, Jenkins and GitHub Actions. No screen needed.
  • Built-in checks. JSON, XML, headers, cookies, schema, response time.

Tool Good for Weak spot

Plain Java HttpClient Full control Lots of code for simple things

Good to know
  • Created by Johan Haleby. Since version 3.0 the package name is io.restassured (older versions used com.jayway.restassured).
  • It uses Groovy inside for JSON paths, and Hamcrest for the checks.
  • It does not test web pages (use Selenium for that) and is not a load-testing tool.
  • It has no test runner or report of its own. You pair it with TestNG or JUnit, and a report tool like Allure or Extent.
Say this in the interview

"REST Assured is a Java library that makes API testing simple. I use it with TestNG and Maven to send requests, check status codes and JSON bodies, and run the tests in a pipeline."
