Kind Where it goes Method Use for
Query param After ? in the URL queryParam() Filter, sort, page: ?page=2

Interview trap: param()

param() guesses for you. On a GET it becomes a query param. On a POST it becomes a form param. Because guessing is risky, use queryParam() or formParam() instead.

Headers and content type

contentType tells the server what the body you send is. accept tells the server what you want back. Forgetting contentType on a POST is the most common reason for a 415 error.

What is Hamcrest?

Hamcrest is a small library of "matchers". A matcher is a word like equalTo that describes what you expect. REST Assured comes with it. You write body("year", greaterThan(2000)) and it reads like a sentence.

Matcher Means Example
equalTo(x) exactly x body("id", equalTo(7))
not(...) the opposite not(equalTo(0))
containsString(s) text has s inside body("title", containsString("Java"))
startsWith / endsWith text begins / ends with startsWith("Eff")
greaterThan / lessThan number compare lessThan(50f)
hasSize(n) list has n items body("books", hasSize(3))
hasItem(x) list contains x hasItem("Clean Code")
hasItems(a, b) list contains all of these, any order hasItems("A", "B")
contains(a, b) list is exactly these, same order contains("A", "B", "C")
containsInAnyOrder(...) exactly these, any order
everyItem(m) all items match m everyItem(greaterThan(0f))
notNullValue() / nullValue() exists / is null body("token", notNullValue())
empty() list or text is empty body("errors", empty())
Trap 1: decimals are floats

REST Assured reads 32.5 as a float. So write equalTo(32.5f). With plain 32.5 (a double) the test fails even though it looks the same. Very large whole numbers are long: 5000000000L.

Trap 2: hasItems vs contains

hasItems("A","B") passes for the list [A, B, C]. contains("A","B") fails for it, because contains wants the whole list.

Check more than one thing in one go

If more than one check fails, REST Assured reports all of them in one message (for example "2 expectations failed"). You see every problem in one run.

Check with plain Java asserts too

The text inside body("...") is a path into the JSON. REST Assured uses a Groovy path style called GPath. With it you can even filter lists and add numbers up.

You want Path Result for the sample below
A top-level value shop "Book Corner"
Inside an object owner.city "Pune"
One list item books[0].title "Clean Code"
The last item books[-1].title "Java Concurrency in Practice"
One field of every item books.title a list of 4 titles
How many items books.size() 4
Filter a list books.findAll { it.price > 30 }.title titles of books above 30
Find one item books.find { it.id == 2 }.author "Joshua Bloch"
Add up numbers books.price.sum() 156.49
Biggest / smallest books.price.max() 50
How to read { it.price > 30 }

it means "the item I am looking at right now". findAll keeps every item where the test is true. find returns the first one.

Careful
  • Inside Java strings use single quotes for text: "books.find { it.author == 'Joshua Bloch' }.id"
  • Key with a dash or space? Wrap it in single quotes: "data.'first-name'"
  • JSON that is a list at the top: use [0].id for an item, and size() for the count.

Real flows have many steps: log in, get a token, create a book, get its id, then read or delete it. To do this you extract a value from one response and feed it to the next call.

Ways to get values out

Method Gives you
path("a.b") any value (type guessed)
jsonPath().getString / getInt / getList / getMap a value of the type you ask for
asString() the full body as text
response() the whole Response object
as(Book.class) a Java object (see POJO section)
Common error: ClassCastException

A JSON number can arrive as Integer, Long or Float. If you write long id = ...path("id") but it came as Integer, Java throws an error. Use jsonPath().getLong("id") to be safe.

Sharing data between test methods

  • Keep it in a field: private String token; set in @BeforeClass.
  • Keep tests independent if you can. Each test creates its own data and cleans up.
  • If one test truly needs another, use TestNG dependsOnMethods (use rarely).

Many APIs are locked. Authentication is how your test shows it has the right to enter.

Type How it works REST Assured
Basic Username and password, sent with every call auth().basic("user","pass")
Preemptive basic Same, but sent in the first call auth().preemptive().basic(...)
Bearer token Log in once, then send the token header("Authorization","Bearer "+token)
OAuth 2 Get an access token from an auth server, send it as bearer auth().oauth2(token)
API key A secret key in a header or in the URL header("x-api-key", key) or queryParam("key", key)
Form Log in through a login form auth().form("u","p", config)
Interview favourite: challenged vs preemptive

With plain basic(), REST Assured first sends the request without credentials. The server answers 401. Then REST Assured sends it again with credentials. That is two calls. preemptive().basic() sends the credentials the first time, so there is one call. Use preemptive when the server does not send a proper 401 challenge.
